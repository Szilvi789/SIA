# Auditing public source before pushing

Private runtime content belongs outside the Git clone. See [private data and application modes](private-data.md) for the application storage setup. Git protections are an additional safeguard: `.gitignore` does not protect a file that was already tracked or added with `git add -f`.

## Install local protection

Requirements: Git, the project's supported Node.js version, Python 3 with `venv`/`pip`, and `tar` (included in current Windows and macOS installations).

From the repository root, on Windows PowerShell or macOS Terminal:

```text
node scripts/install-privacy-tools.mjs --hooks
node scripts/privacy-audit.mjs
```

The installer creates an isolated, Git-ignored `.local-tools/privacy/venv` for **pre-commit 4.7.0**, installs both local Git hooks, and downloads **Gitleaks 8.30.1** from its official GitHub release. It verifies the archive against a SHA256 pinned in the installer before extracting or executing it. Windows x64/ARM64, macOS Intel/Apple silicon, and Linux x64/ARM64 are supported.

Existing custom hooks or a custom `core.hooksPath` cause setup to stop with integration guidance; they are never silently replaced. Rerunning setup can refresh hooks generated by pre-commit. Hooks are installed before the download, so a download failure leaves protection enabled and failing closed until the scanner is installed. A different existing local scanner binary requires manual review before replacement.

For offline machines or a corporate proxy, download the appropriate official release archive through your approved network setup, then run:

```text
node scripts/install-privacy-tools.mjs --hooks --archive /path/to/official-release-archive
```

Use a quoted path on Windows if it contains spaces. SHA256 verification still applies. Python package installation also requires network access or an approved local pip package cache. Proxy credentials are never saved in this repository. Reinstall hooks after moving a clone to a different directory or computer, because generated local hooks refer to the local Python environment.

## What runs locally

`.pre-commit-config.yaml` uses the open-source [pre-commit framework](https://pre-commit.com/) to invoke the same Node audit in two modes:

- **Before commit:** inspect every staged index blob, including previously tracked files. Replacing a secret in the working copy does not hide its staged version.
- **Before push:** inspect all file versions and commit messages reachable from every local Git ref, plus the outgoing revision when supplied by the hook framework. This covers multiple branches in one push and a document or secret added and removed in earlier commits. It intentionally also checks older reachable commits instead of trusting a remote baseline.

The full manual command inspects the current index, tracked working files, nonignored untracked files, and all reachable local Git history. It never stages, commits, pushes, untracks files, deletes application data, or changes Git history.

```text
node scripts/privacy-audit.mjs
node --test scripts/privacy-audit.test.mjs
```

Audits reject known runtime directory names, local environment/configuration files, OAuth/credential files, office documents, email/calendar/contact exports, CSV/TSV exports, screenshots/photos and other bitmap images, database files/dumps, certificates/private keys, and archives. Suspicious text/Markdown filenames such as resumes, passports, and bank statements also require review. They inspect dump signatures and explicit private-data markers even when filenames look harmless. Symlinks and submodules require explicit manual review and are blocked by default. Application source, public Markdown documentation/example rules, generic JSON configuration, and Flyway SQL migrations remain permitted. SQL must live under `backend/src/main/resources/db/migration/` with a versioned or repeatable migration name; database dump content is still rejected there.

Gitleaks checks the actual staged/historical bytes. Each blob is scanned under both its original name and a neutral text filename, so detector defaults for lockfiles, SVGs, Maven wrappers, or scanner configuration cannot conceal an embedded token by path. Inline allow comments and repository fingerprint-ignore files do not bypass the scan. Detector output is captured privately; reports show only filenames, categories, and scope. No matching secret text is printed. Temporary scan copies use the operating system's temporary directory and are removed when the audit finishes, including error paths.

A scanner that is missing, has the wrong pinned version, or fails to finish makes the full audit and both hooks fail. For diagnostics only:

```text
node scripts/privacy-audit.mjs --skip-secrets
```

This clearly reports a **PARTIAL** audit; hooks reject this option. It is not a substitute for a successful full audit before pushing.

## Synthetic document exceptions

Prefer synthetic text fixtures in source/tests. If a test needs a restricted document format, or the public application needs an image asset, add its exact repository path, SHA256, and a clear synthetic/public purpose to `scripts/privacy-policy.json` under `syntheticFiles`. Review both the file and policy change, including image metadata. Changing its bytes invalidates the exception. Exceptions never permit credentials, certificates, database files/dump content, runtime directories, or secret-detector findings. The initial policy has no exceptions. Source image files are not broadly ignored; they remain reviewable and need this explicit audit approval.

## Git and CI safeguards

`.gitignore` excludes private runtime folders, environment/credential files, local configuration, database volumes/dumps, and backup archives. `.gitattributes` makes line endings predictable on Windows/macOS and identifies binary formats; attributes do not prevent files from being tracked. Necessary application source and migration files are not broadly ignored.

`.github/workflows/privacy.yml` repeats the tests and full audit on pushes and pull requests using the checksum-verified CLI. Its GitHub Actions dependencies are pinned by commit SHA and receive read-only repository access. CI runs after content has reached GitHub, so local hooks and the manual pre-push audit are the first protection.

## Validation and limits

The implementation was validated on the current Windows checkout with tests covering staged/index inspection, forced tracking despite ignore rules, removed historical documents/secrets, dump detection, migration exceptions, synthetic hashes, missing-scanner failure, temporary-file cleanup, real scanner detection, and scanner path exclusions. The initial complete audit inspected **763 file versions with zero findings**; rerun it after changes because the file-version count naturally changes. A successful scan is not proof that arbitrary personal prose or every possible secret format is absent.

Local hooks can be deliberately bypassed or removed, and scanners have false positives and false negatives. Keep human review of `git status`, `git diff --cached`, and `git ls-files` before publishing. Store real documents outside the clone instead of depending on filenames or scanning. Git author names/emails and commit messages are also public metadata when pushed. Encrypt disks/backups and use OS credential storage according to your own device requirements.

If sensitive material has already been pushed, adding an ignore rule or removing the latest copy does not make the older content private. Rotate exposed credentials and assess repository/history remediation separately with explicit user approval. This work does not automatically rewrite history, delete files, commit, or push anything.
